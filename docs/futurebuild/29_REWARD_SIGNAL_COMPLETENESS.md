## §1 — Why this audit exists

The substrate generated by the prod-par6perf forward-cache run (391 shards × 1024 chunks × 12 embedders ≈ 4.9 M packed records) is the **primary** reward-signal source for ME-JEPA training. But there are many MORE reward signals derivable from durable reality that the system should be persisting + leveraging. This audit:

1. Enumerates every reward signal across 8 tiers.
2. Marks which signals are captured today vs pending.
3. Maps each pending signal to its TASK-RWD-NNN sub-task.
4. Defines the completeness acceptance gate.

Without explicit completeness tracking, the system silently leaves signal on the table — and silent gaps in reward density are the dominant failure mode for JEPA-class training.

## §4 — Mapping to teleological constellation chain

Per the operator's framing (and LeCun's emphasis), teleological constellations are intent-linked chains. Each arrow in the chain is one or more reward signals from §2:

| Chain arrow | Reward signal(s) | Tier |
|---|---|---|
| Operator goal | UserPromptSubmit text embedding | 7 (TASK-RWD-207) |
| Agent claim | Atomic-claim parser output (Q1 head input) | 7 |
| Edit event | Pre/Post SHA + AST diff (E_AST + E_Witness) | 3 + 8 |
| AST delta | Typed structural delta (`python_diff_chunk_map`) | 3 |
| Embedded chunk constellation | 12-embedder forward cache | 2 |
| Frozen instrument readings | 15-slot panel | 1 + 3 + 4 + 5 |
| Oracle outcome | E_Oracle (Docker exit code + exception class) | 1 |
| Operator feedback | `CF_MEJEPA_OPERATOR_OVERRIDES` | 1 |

**ME-JEPA trains on chains, not individual signals.** A single chain run produces a complete reward trajectory; multiple chains build the per-fingerprint cell statistics; many cells build the calibrated catalog.

## §5 — Acceptance gate

The reward-signal completeness audit is **GREEN** when ALL of the following hold:

1. **Per-tier coverage ≥ 95%.** Every tier in §2 has ≥ 95% of its signals captured to durable storage. Verified by `mejepa_audit_reward_signals` MCP tool returning per-tier coverage report.
2. **Per-fingerprint training set is multi-tier.** Per-fingerprint training data per #309 includes signals from all 8 tiers, not just oracle. Verified by inspecting `CF_MEJEPA_FAILURE_FINGERPRINTS` schema and confirming feature columns span tiers 1-8.
3. **Lifelong learning loop is reward-signal-driven.** Replay buffer (#287 / TASK-RWD-210) consumes operator override events at 6× weight + drift-flagged cells at 3× + adversarial cases at 4×.
4. **Active-learning queue auto-extends catalog.** Novel-pattern detection (#286 / TASK-RWD-211) clusters Unknown chunks → operator labels → catalog grows. Verified by lifecycle FSV.
5. **Constellation freshness scheduler runs.** Per-cell freshness audit (#271 / TASK-RWD-212) re-centroids cells whose member set shifted significantly.
6. **No silent signal drops.** When an embedder forward fails, when a static-graph stage skips a chunk, when an instrument can't compute a value — these are logged as fail-closed events to a new `CF_MEJEPA_SIGNAL_DROP_LOG`, not silently zeroed.

## §6 — How to use this doc

1. **Before claiming a TASK-RWD-NNN issue**, read this doc top-to-bottom to understand which tier the signal belongs to and which other signals it interacts with.
2. **When implementing a new instrument**, register it in §2 (this doc) AND in `05_EMBEDDER_SIGNAL_MAP.md` + `docs/whitepapermejepasystem/05_FROZEN_INSTRUMENT_PANEL.md`. The instrument is part of the frozen target panel by construction; its computation must be deterministic and have zero trainable parameters.
3. **When adding a new reward signal that wasn't anticipated** (e.g., from an operator-directed expansion), file it as a new TASK-RWD-NNN sub-task under #315 + add it to the §2 tier table.
4. **At the per-cell stratified evaluation step** (Phase G ship gate), verify that every cell's training data spans tiers 1-7 (tier 8 is audit-only, doesn't enter training loss). Cells missing tier coverage are flagged for completeness backfill before the per-cell correlation ≥ 0.95 check.
