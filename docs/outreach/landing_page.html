What it is

Most JEPA work emphasizes representational quality on natural images or video. This paper is one level up: what does it take to make every step of a JEPA runtime — data ingest, multi-instrument latent panel materialization, action-conditioned training, planning, surprise recording, and artifact provenance — physically auditable end-to-end on a single commodity GPU?

Dynamic / ME-JEPA is one Rust binary. New domains ship as a TOML manifest. Every operation writes typed rows into 25 RocksDB column families plus an append-only audit log; a structurally separate verifier reads everything back. The same code path runs three domains: counter_world, gridworld_5x5, and a new career_taxonomy.v1 public-taxonomy benchmark derived from O*NET 30.2 starting at Software Developers (15-1252.00).

Headline numbers

Career-taxonomy validation cosine: 0.905 ± 0.044 across 5 seeds (BCa 95% CI [0.861, 0.931])
Test cosine: 0.868 ± 0.068 (BCa [0.806, 0.912])
Validation action-contrast accuracy: 0.960 ± 0.043
A3 action-removed ablation: collapses to validation cosine 0.790 — exactly as the design predicts and the verifier confirms.
Reproducibility artifact: deterministic Docker tar + Apptainer SIF + per-seed bundles, all SHA-chained back to the source.

The second contribution: bundles as training data

Each immutable bundle the runtime produces is itself a structured training-data artifact. Most bytes are deterministic functions of a public source ZIP; the small model-output slice is paired with the observed next-state and with random-init / shuffled-target baselines in the same record; counterfactual ablations and failed runs are persisted as first-class records. This positions bundles as a new class of training data — audited execution traces with cryptographic provenance — with substantially lower recursion-replacement collapse hazard than pure synthetic data.
