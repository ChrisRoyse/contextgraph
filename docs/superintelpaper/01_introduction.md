# 1. Introduction

## 1.1 The verification bottleneck

Machine generation of artifacts — code, proofs, images, diagnoses — has outrun human verification. A coding agent emits edits faster than a reviewer can read them, and the asymmetry widens with model capability: the better the generator, the larger the backlog of unverified output. The binding constraint on machine throughput in any domain with a quality bar is therefore not generation but **verification**.

Verification can in principle be automated whenever the domain possesses a **deterministic oracle** — a machine-runnable function that returns ground truth for a candidate artifact. Code has one (run the tests in a container). Theorem proving has one (a proof checker). Drug binding has a wet-lab assay; weather has the observation archive; chess has engine search. The question this paper answers is: *under what conditions can a learned predictor stand in for that oracle so reliably that human review of machine-generated artifacts becomes statistically unjustified?* I call a domain in which such a predictor exists a domain in which **operational super-intelligence** has been reached, and I make the term falsifiable.

## 1.2 Thesis

I advance three linked claims and instantiate them on a live system.

1. **The oracle is the anchor, and its self-consistency is a ceiling.** A predictor can never agree with the oracle more often than the oracle agrees with itself. Oracle quality is therefore not a detail but the first quantity to measure, and it decomposes into two distinct axes — *flakiness* (does the oracle reproduce its own verdict?) and *validity* (does the oracle's verdict track the property one cares about?) — which the recent SWE-bench literature shows are independently violable [Aleithan2024; Wang2025; OpenAI2026].

2. **A domain predictor is a grounded association engine.** This is the symbol-grounding result of cognitive science, transplanted. Harnad's dictionary-go-round [Harnad1990] shows that meaning defined only by reference to other meanings is circular; Vincent-Lamarre et al. [VincentLamarre2016] make it quantitative — a dictionary's definitional graph reduces to a **grounding kernel of ≈10%** and a **minimum grounding set (a minimum feedback vertex set) of ≈1%** from which all else is recoverable by association. The predictor is the same object: a vast web of associations over candidate artifacts, anchored at a small *grounding kernel* of oracle-labeled artifacts. The oracle is the anchoring channel; the kernel is the minimal set of artifacts that must pass through it. Mollo & Millière's *Vector Grounding Problem* [Mollo2023] extends this from symbols to the vectors a modern panel actually computes over, and supplies the criterion I adopt: a representation is referentially grounded when it stands in causal-informational relation to a worldly outcome *and* was selected for carrying that information.

3. **A grounding kernel can exist only if the observation panel carries the oracle's bits.** This is the load-bearing engineering result. The mutual information `I(panel; oracle)` upper-bounds — by the data-processing inequality [CoverThomas2006] — what *any* predictor reading the panel can know about the outcome. If the panel shares fewer than the oracle's worth of bits with the verdict, no predictor, no kernel search, and no calibration can close the gap; the deficit is **upstream**, in the sensors. This converts "is this architecture viable?" into a cheap measurement that runs before any model is trained.

## 1.3 Contributions

- **A falsifiable, oracle-bounded definition of domain super-intelligence** (§3), expressed as a single predicate over six measurable tiers, with the threshold derivation and the explicit statement that the correlation target is capped by oracle self-consistency.
- **A theory of the oracle as grounding anchor** (§2), separating flakiness from validity and showing why each bounds the achievable predictor in a different way.
- **The grounding-kernel reframe** (§4): the generalization of the dictionary ≈1% minimum grounding set to an arbitrary domain, with the oracle as anchor and the kernel as the minimal set of artifacts to ground; and the resulting reframe of the ship-gate from "correlate over the whole corpus" to "ground the minimal kernel, derive the rest."
- **The substrate-sufficiency test** (§5): `I(panel; oracle) ≥ τ_MI` as a method-independent existence test for a grounding kernel, with the estimator stack and the data-processing/Fano argument for why it cannot be evaded by better modeling.
- **An empirical instantiation with a clean negative result** (§6–§7): on ME-JEPA-Code (binary `Pass/Fail` for Python changes against a Docker test oracle, SWE-bench Lite, 300×8), the oracle anchor is noiseless on the flakiness axis (`oracle_self_consistency = 1.0`) yet the 9-sensor panel carries only `I(panel; oracle) ≈ 0.46` bits about a ≈1-bit outcome — far below the `0.95`-bit threshold. A per-sensor decomposition localizes the deficit: the panel measures code *form* (similarity/retrieval embeddings) and is nearly blind to code *behavior*; no sensor is load-bearing; signal survives only in the single purely-syntactic perturbation class.
- **A method, not a guess, for fixing it** (§6.5): assemble the panel from candidate sensors selected by their *measured marginal bit-contribution* to the oracle — acquire, run, measure `ΔI`, keep what carries outcome signal, stop at sufficiency — after which the kernel becomes well-posed.

## 1.4 What is and is not claimed

This paper defines super-intelligence **operationally and per-domain**: a predictor that replaces a human verification function at higher accuracy and machine throughput, against a domain that has a deterministic oracle. It is **not** a claim about general intelligence, sentience, understanding, or any property lacking a deterministic oracle. The claim is falsifiable precisely because it is narrow: every term in the predicate (§3) is a number with a source of truth, and the central empirical result of the instantiation is a **falsification** — the current panel provably cannot reach the gate — which is the kind of result the framework is built to produce early and cheaply.

I also state the honest boundary up front (developed in §11): association is circular unless grounded, so the entire edifice rests on the oracle being a faithful anchor. Where the oracle is invalid (weak tests admit wrong artifacts) or contaminated (the artifacts leaked into a sensor's pretraining), the bits the panel appears to carry are bits about the wrong thing, and the super-intelligence claim is void regardless of the correlation achieved. The framework's job is to make each of these failure modes a measurement rather than an assumption.
