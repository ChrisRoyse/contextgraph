# 11. Conclusion

The bottleneck on machine output in any domain with a quality bar is verification, not generation. This paper has argued that verification can be automated — to the point where human review becomes statistically unjustified — exactly when three separable, measurable conditions hold, and that the conditions are best understood through the lens of symbol grounding.

**The oracle is the anchor.** It is the single point where the system touches non-linguistic reality, and its quality decomposes into two independently-violable axes — flakiness (does it agree with itself?) and validity (does it track the real property?). Self-consistency is a hard ceiling on achievable correlation; validity conditions the entire claim. Neither is an assumption in this framework; both are measurements.

**A domain predictor is a grounded association engine.** Harnad's dictionary-go-round and the Vincent-Lamarre ≈1% minimum grounding set transplant directly: the predictor is a web of associations over candidate artifacts, anchored at a small grounding kernel. The oracle is the anchoring channel; the kernel is the minimal set of artifacts to send through it. Grounding a domain means grounding the kernel and deriving the rest — not oracle-testing everything and correlating.

**A kernel exists only if the panel carries the oracle's bits.** This is the operational heart. The mutual information `I(panel; oracle)` upper-bounds — by the data-processing inequality — what any predictor, any kernel search, or any calibrator reading the panel can achieve. It is therefore a method-independent existence test that runs before training and can falsify an architecture cheaply.

Instantiated on a live system — binary `Pass/Fail` for Python changes against a Docker test oracle — the framework produced a clean, useful negative result. The anchor is noiseless on the flakiness axis (`oracle_self_consistency = 1.0`), yet the 9-sensor panel carries only `I(panel; oracle) ≈ 0.46` of the ≈1 bit the verdict requires. The per-cell and per-sensor decompositions localize the deficit exactly: the panel measures code *form* and is nearly blind to code *behavior*; no sensor is load-bearing; signal survives only in the single purely-syntactic class. This is not a tuning failure that more training or calibration could fix — by the data-processing ceiling those operations are bounded by the same 0.46 bits — it is a substrate failure whose fix is upstream, in the sensors.

That diagnosis is the framework paying for itself. Instead of grinding a correlation number against a fixed corpus (and risking Goodhart on proxy metrics), the path forward is prescribed without guessing: assemble a panel of outcome/causal and execution-derived sensors selected by their *measured* marginal bit-contribution to the oracle, accept it only when `I(panel; oracle)` clears the threshold with the behavioral cells lifted off zero, and only then compute the grounding kernel and let the predictor approach the gate. The headline metric becomes kernel-coverage, not corpus-correlation.

The general claim, restated: **operational super-intelligence in a domain reduces to a clean oracle, a panel sufficient to carry the oracle's bits, and the minimal grounded kernel from which the rest is recovered by association.** Each is separately measurable and separately falsifiable. The framework is domain-agnostic; only the oracle, the panel, the corpus, and the matrix are domain-specific. And the domains it can reach are exactly the domains that have a deterministic anchor — which is the same boundary Harnad drew thirty-five years ago, now with a number attached to it.

The single most important open task is not a model improvement. It is to measure the oracle's *validity*, so that a future Tier-1 pass means the system agrees with reality rather than with the oracle's mistakes. Until then, the framework's most valuable output is the one demonstrated here: telling you, cheaply and early, exactly where a domain's super-intelligence is blocked — and in this case, that it is blocked in the sensors, not the model.
