# 7. Bundles as a Training-Data Class

The bundles produced by the Dynamic/ME-JEPA runtime are not only a
verification artifact for §8. They are also a structured training-data
artifact in their own right. This section argues that the bundle
constitutes a *new class* of training data, distinct from web text,
LLM-generated synthetic data, and rejection-sampled chain-of-thought
corpora. I give the taxonomy, the per-bundle anatomy of training
signal, the model-collapse hazard analysis, and the use cases for
which the data class is appropriate (and inappropriate).

## 7.1 The Synthetic-Data Taxonomy as It Stands

The current frontier consensus on training-data quality and
model-collapse risk has four operative categories:

1. **Real source data** — text, images, audio, structured records
   captured from human or natural processes. High value, finite
   supply; the substrate against which collapse is measured.

2. **Pure model-generated synthetic data** — outputs of a generative
   model fed back as training data with no external validator.
   Shumailov et al. [2023; 2024] showed that this pattern, *under
   recursive replacement*, irreversibly removes distribution tails;
   in late stages the model converges to a distribution that "carries
   little resemblance to the original" [Nature, 2024].

3. **Verifier-grounded synthetic data** — model outputs filtered by
   an external validator (math checker, unit test, physics envelope,
   step-level human label). The current best-practice synthetic
   reasoning corpora — SYNTHETIC-1 [Prime Intellect, 2025], Enigmata
   [Seed, 2025], the PRM800K dataset of step-level labels [Lightman
   et al., 2023] — sit here. The validator anchors every retained
   record to ground truth; rejection-sampled CoT is the canonical
   instance.

4. **Process-trace data anchored to a deterministic system over real
   source** — execution traces, code-execution-grounded supervision
   [Jung et al., 2025], world-model rollouts [Hafner et al., 2023;
   Schrittwieser et al., 2019], and other settings where the bytes
   of the dataset are *deterministic functions of a real source plus
   a runtime*, with model outputs forming only a small slice of the
   record and paired with independent verification.

The collapse-vs-retain distinction matters: Gerstgrasser et al. [2024]
showed that even with the same generators, *accumulating* synthetic
data alongside real data avoids the collapse Shumailov demonstrated
for *replacement*. The pattern that breaks generative models is not
"synthetic" per se — it is recursive replacement of real distributions
by model-induced distributions.

## 7.2 What a Bundle Actually Contains as Training Signal

A research-smoke career bundle (§3, §4, §6) is a directory tree of
typed records. Read as a training-data corpus, it decomposes into
three byte-slices with very different provenance:

**Slice 1 — Deterministic-from-public-source.** Generated by walking
O\*NET 30.2's related-occupation graph from `15-1252.00` Software
Developers under a fixed seed. These records are deterministic
functions of `(source_zip_sha256, walk_seed, domain_pack_hash)`:

- `dj_raw_events`, `dj_normalized_states`, `dj_actions`, `dj_outcomes`,
  `dj_transitions` (1,004 / 1,000 / 1,005 / 1,000 / 1,000 rows for a
  1K-event career bundle);
- `dj_instrument_readings` (10,000 rows): outputs of declared frozen
  instruments — frozen, so reproducible from the same input;
- `dj_latent_panels` (1,000 rows): the ten declared panel slots filled
  for each event;
- `dj_trajectories`, `dj_dataset_shards`: structural records with
  leakage checks, train/val/test = 699/200/100 deterministically.

A reviewer can reproduce these byte-for-byte from the public ZIP
(`b5479271…7453741`) and the published walk seed. This slice carries
*no* model outputs whatsoever.

**Slice 2 — Tiny-model outputs paired with observed targets.** For
each plan invocation the runtime emits:

- `dj_predictions` (6 rows per bundle): predicted next-panel for the
  state plus the five candidate actions;
- `dj_plan_traces` (1 row): the candidate set, predictions per
  candidate, guard decisions per candidate, utility scores, selected
  action, and the model artifact's SHA-256;
- `dj_guard_decisions` (5 rows): per-candidate guard verdict;
- `dj_surprise_events` (0 or 1 row): when observed-vs-predicted delta
  exceeds threshold.

These *are* model outputs from the 15{,}344-parameter career predictor.
Crucially, every prediction lives in the same record as the
deterministic *observed* next-state from Slice 1, plus the
`random_init_cosine` and `shuffled_target_cosine` baselines from §7.1
— so the model output is paired with both ground truth and a
calibration baseline at the row level. The numerical values of these
baselines for the released artifact are tabulated in §8.1.

**Slice 3 — Independent verifier readbacks.** The runtime persists,
through a code path structurally separate from the writer:

- `dj_verification_runs` (1 row per domain): the FSV harness's
  re-decoded state of every prior CF;
- `dj_audit_log` (3,019 rows for a 1K career bundle): chronological
  `(operation, before-counts, after-counts, hashes, typed status)`
  ledger;
- `paper_tables/table_edge_cases.csv` (11 rows): typed
  `(scenario, error_code, field_path, remediation)` records;
- `paper_tables/table_ablation*.csv` (6 ablation rows + paired tests):
  counterfactual A0–A5 evidence;
- `artifact_hashes.json`: registry-vs-recomputed file hashes;
- `onet_source_preflight.json`: per-bundle source-ZIP integrity
  evidence.

Slice 3 is not generated by the model under test. It is a separate
verifier physically re-reading Slice 1 and Slice 2 and emitting an
external auditing trace.

The proportion is roughly: **Slice 1 ≫ Slice 3 > Slice 2** by byte
count for a typical career bundle. Predictions/plans/guards account
for tens of rows; deterministic walk records and audit log account
for thousands.

## 7.3 Properties Relative to Existing Training-Data Classes

| Property | Web text | Pure synthetic LLM CoT | Rejection-sampled (SYNTHETIC-1, PRM800K) | Code-execution traces [Jung et al., 2025] | World-model rollouts (Dreamer, MuZero) | **ME-JEPA bundles** |
| --- | :---: | :---: | :---: | :---: | :---: | :---: |
| Anchored to real source | yes | no | partial (problem set) | yes (program) | indirectly | **yes (O\*NET ZIP, hashed)** |
| Cryptographic provenance to source | rare | no | no | rare | no | **yes, every record** |
| External verifier on each step | no | no | yes (validator) | yes (interpreter) | no | **yes (FSV)** |
| Counterfactuals as first-class records | no | sometimes | no | no | sometimes | **yes (A0–A5)** |
| Failed runs preserved | no | usually discarded | discarded by rejection | discarded | discarded | **yes, by policy** |
| Typed schema on every row | no | no | partial | yes | yes | **yes (TOML domain pack)** |
| Recursion-replacement risk | n/a | high | medium-low | low | medium | **low** |

The line-item **ME-JEPA bundles ≠ rejection-sampled CoT** is the most
counter-intuitive but the most important. Rejection sampling *throws
away* the negative samples. The data the next-generation model sees
is the validator-passing slice only — which is precisely how the
distribution narrows over iterations, even with a validator. ME-JEPA
bundles persist the failures: the seed-43/seed-45 ablation failures
(§8.7), the rc1 missing-binary release-candidate failure, the
A3 negative-control ablation that *deliberately* collapses to
val cosine 0.790. These are not noise; they are the tail of the
distribution preserved by construction.

## 7.4 Collapse-Hazard Analysis

For the dangerous sense of *model collapse* — the Shumailov / Curse-of-
Recursion phenomenon in which recursively generated content displaces
real source data and the resulting model loses distribution tails —
ME-JEPA bundles have a substantially lower hazard than typical
synthetic data. Three reasons:

**Reason 1: The bulk of the bytes are not model-generated.**
Slice 1 is a deterministic function of the public O\*NET ZIP plus a
fixed walk seed. Slice 3 is a separate verifier's readback. Only Slice
2 is model-generated, and Slice 2 is small. Adding the bundle to a
real-data corpus is closer to *adding a structured reference dataset*
than to *recursive synthesis*.

**Reason 2: Accumulation, not replacement.** The intended use is to
*accumulate* bundle data alongside existing corpora. Per Gerstgrasser
et al. [2024], accumulation does not collapse even with the same
generators that cause collapse under replacement. The artifact ships
under PolyForm Noncommercial 1.0.0 with a license that permits this
accumulation pattern in research and educational replication settings.

**Reason 3: Tails are explicitly preserved.** The defining symptom of
model collapse is loss of distribution tails. ME-JEPA bundles
preserve tails by three structural mechanisms: (a) the failed-bundle
preservation policy keeps `*_v1`/`*_v2` failed runs alongside the
final passed runs; (b) the 11 edge-case rows per bundle are typed
tail-of-distribution training examples by construction; (c) the A3
negative-control ablation forces a low-cosine tail row into every
bundle.

The remaining collapse-hazard slice is Slice 2 (predictions,
plans, guards). If a downstream training run treats the *predictions*
column as ground-truth labels and trains a larger model to mimic them,
the 15K-param predictor's biases would propagate. The mitigation built
into the data class is that every prediction row is paired with the
deterministic observed-next-state from Slice 1 and the random-init /
shuffled-target baselines — so the natural supervised signal is
`(state, observed-next-state)`, with predictions and guards available
as auxiliary process-supervision targets rather than primary labels.

## 7.5 What This Data Class Is Useful For

These are the training settings for which bundles are a high-value
signal, ordered by what I would expect to invest in first:

1. **Agentic / tool-use models that operate the runtime.** The plan
   trace is the canonical record an agent needs to learn the
   *predict → guard → act → log → audit* loop on a typed action space.
   Each plan trace is a five-candidate action search with verifiable
   structure: state, candidate set, predictions, guard verdicts,
   utility scores, selected action, model artifact hash, persistence
   audit row. This is the highest-value use case and the one closest
   to the system's design intent.

2. **Process-supervised reasoning data anchored to a verifier.**
   Lightman-style step-by-step supervision [Lightman et al., 2023],
   but where the verifier is a *separate code path* that physically
   re-reads the source of truth rather than an LLM-judge. Bundle
   audit-log rows are the per-step labels; Slice 3 is the verifier.

3. **Audit / FSV-style reasoning.** Teaching a model to always emit
   before/after counts, cite a SHA-256, and verify via a structurally
   separate path. This pattern is rare in current training corpora
   and would be valuable for any system that needs to operate on
   regulated or auditable data. The audit-log + edge-case-row pair
   is the corpus.

4. **Error-typing and remediation.** The 11 edge-case rows + 6
   aggregate-level edges + 7 release-level edges per release form a
   small but high-quality corpus of `(scenario, typed-error,
   field-path, remediation-string)` quadruples. Almost no public
   dataset has this shape.

5. **Schema and domain-pack composability.** TOML domain packs →
   typed records → typed errors form a high-quality corpus for
   training models that read schemas and emit valid records. The
   three included domain packs (counter\_world, gridworld\_5x5,
   career\_taxonomy.v1) provide three controlled variants of the
   same record contract.

6. **World-model imagination data, scoped.** The plan traces are
   MuZero/Dreamer-style imagined-rollout data on a typed action
   space — useful for training small specialized planners that need
   to reason about typed action effects. Not a substitute for general
   physics or world data.

7. **Code-execution-grounded supervision over a domain runtime.** In
   the spirit of [Jung et al., 2025], who use program execution to
   ground CoT supervision, ME-JEPA bundles can be used to ground
   supervision for *runtime operation* rather than program execution.
   The audit log is the deterministic execution trace; the verifier
   readbacks are the ground truth for each step.

## 7.6 What This Data Class Is *Not* Useful For

A bundle teaches the *runtime's behavior on a bounded slice of
O\*NET*, not "careers." Specifically:

- **General world knowledge.** The taxonomy walk covers 218 selected
  occupations, 4 clusters, and 5 actions. A model trained on the
  bundle learns this corner of O\*NET, not the labor market.
- **Continuous-time or fine-grained temporal dynamics.** Events are
  step-indexed integers; the time field is an i64 in `[0, 10^6]`.
- **Modalities outside the declared instruments.** No images, audio,
  or text-token sequences appear in any record.
- **Open-ended generation.** The bundle has no free-form natural-
  language outputs; everything is typed.
- **Adversarial or safety-critical planning.** The 5-action candidate
  set is intentionally small for the smoke benchmark.

A model trained naively on a bundle as if it were a general-purpose
text corpus will pick up the schema and the runtime's habits, which
is sometimes useful and sometimes not. Treating the bundle as broad
world knowledge would be a category mistake.

## 7.7 Naming the Class

I propose **"audited execution traces"** (alternatively
**"verifier-grounded process-trace data with cryptographic
provenance"**) as the working name for this class of training data.
The defining properties, restated tightly:

> Most of the bytes are deterministic functions of a public source
> plus a runtime; the small model-output slice is paired in the same
> record with an independent verifier readback; counterfactuals and
> failures are persisted; every record carries a SHA-256 chain back
> to the source.

The closest existing class is code-execution-grounded supervision
[Jung et al., 2025], which similarly extracts verifiable step-by-step
traces from deterministic program execution. ME-JEPA bundles
generalize this idea from program execution to *typed domain-pack
runtime execution* and add three properties that code-execution
traces do not routinely carry:

- **Cryptographic provenance to a public source ZIP** (Slice 1
  recoverable by SHA-256 from the public download URL, with the per-
  edge walk hash recorded inline);
- **Independent verifier readback as a separate record class**
  (Slice 3 as `dj_verification_runs` and `dj_audit_log` rather than
  as inline assertions in the trace itself);
- **Typed counterfactual ablations as first-class records** (A0–A5
  persisted into `dj_verification_runs` and surfaced through
  `paper_tables/table_ablation*.csv`).

## 7.8 Recommendations for Downstream Training

If a future system uses Dynamic/ME-JEPA bundles as part of its
training corpus, the following pattern reduces the risk of importing
the runtime's biases while preserving the data class's strengths:

1. **Treat Slice 1 (deterministic walk) and Slice 3 (verifier
   readbacks) as primary signal.** They are the largest, lowest-risk,
   highest-provenance portion of the bundle.

2. **Treat Slice 2 (predictions, plans, guards) as process-supervision
   targets paired with the observed next-state**, not as primary
   labels. Specifically, the supervised label for next-state should
   be the deterministic observed next-state from the same record;
   predictions and guards are auxiliary targets used for process-
   reward modeling [Lightman et al., 2023] or for teaching the
   downstream model to emit guard verdicts.

3. **Keep failed bundles in the corpus.** They are precisely the
   tail-preserving slice that prevents distribution narrowing under
   the Shumailov pattern.

4. **Mix with real corpora rather than replacing.** Per Gerstgrasser
   et al. [2024], accumulation avoids the collapse pattern that
   replacement triggers; the bundle is intended to *extend* a real
   corpus, not *replace* it.

5. **Bound the claim to the runtime's competence.** A model trained
   on bundle data has learned the runtime's behavior on the
   benchmark's declared schemas. It has not learned the world the
   schemas approximate.

The result is a downstream model that has learned to operate the
audit-aware runtime: predict, plan, guard, log, verify, fail closed,
and emit typed errors with field paths — a skillset orthogonal to
general world knowledge and currently underrepresented in public
training corpora.
