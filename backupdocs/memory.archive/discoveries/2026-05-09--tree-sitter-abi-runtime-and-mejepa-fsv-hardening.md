# Tree-sitter Runtime ABI Can Block Newer Language Grammars

## What Happened

`cargo test -p context-graph-cli --lib csharp_semantic_extraction_captures_members_and_test_paths -- --nocapture`
failed before semantic extraction could run:

`failed to initialize csharp parser ... Incompatible language version 15. Expected minimum 13, maximum 14`

The C# grammar crate in the workspace is `tree-sitter-c-sharp v0.23.5`, which emits language ABI 15. The
workspace runtime was still `tree-sitter v0.23.2`, whose runtime accepted only ABI 13 through 14. C# therefore
failed at parser initialization even though the grammar crate itself compiled.

## Root Cause

Tree-sitter language grammars carry an ABI version generated by the Tree-sitter CLI, and the runtime is not
forward-compatible with grammars generated by newer CLIs. Mixing a newer grammar crate with an older runtime
causes runtime parser setup to fail closed.

## Fix Applied

Updated all direct workspace `tree-sitter` runtime dependencies used by the relevant crates to `0.26` and ran
`cargo update -p tree-sitter`. The locked runtime is now `tree-sitter v0.26.8`, while grammar crates remain:

- `tree-sitter-c-sharp v0.23.5`
- `tree-sitter-java v0.23.5`
- `tree-sitter-python v0.23.6`
- `tree-sitter-c v0.23.4`
- `tree-sitter-cpp v0.23.4`
- `tree-sitter-rust v0.23.3`

## Why It Matters

DynamicJEPA and the ME-JEPA corpus harness rely on real AST extraction. A parser initialization fallback would
silently remove compiler-language evidence from mutation records. The correct behavior is to keep parser
initialization fail-closed, log the exact language/runtime incompatibility, and keep dependency versions aligned.

## Verification

- `cargo tree -p context-graph-cli | rg 'tree-sitter v|tree-sitter-c-sharp|tree-sitter-java|tree-sitter-rust|tree-sitter-python|tree-sitter-cpp|tree-sitter-c'`
  showed `tree-sitter v0.26.8` with the expected grammar crates.
- `cargo test -p context-graph-cli --lib csharp_semantic_extraction_captures_members_and_test_paths -- --nocapture`
  passed after the runtime update and printed real C# symbols including delegate, event, property, indexer, and test method captures.
- `cargo test -p context-graph-mejepa-corpus -- --nocapture` passed 50 tests after the dependency update.
- Full state verification read back `/tmp/contextgraph-mejepa-corpus-fsv/mejepa-corpus-evidence.json`,
  `/tmp/contextgraph-mejepa-corpus-fsv/split-evidence.json`, and `/tmp/contextgraph-mejepa-corpus-fsv/split-assignments.json`
  after execution and hashed them.
