# 04 Data Pipeline

## Source Of Truth

The canonical data build must produce a manifest, not just JSONL files.

Required manifest fields:

- raw source file hash,
- cleaning script hash,
- embedder versions and hashes,
- constellation IDs and hashes,
- prompt template version,
- record provenance,
- train/eval split,
- contamination gate result,
- style/content/coherence scores,
- anti-memorization overlap scores.

No record enters training without a manifest row.

## Corpus Roles

| Corpus type | Role | Should dominate training? |
|---|---|---|
| Raw Shakespeare speech/verse | style anchor, centroid member, source for cleaned target text | No |
| Cleaned Shakespeare passages | SFT target text, constellation construction, anti-memorization source | Yes, after gates |
| Verified compositional bridge examples | eval/guard fixtures unless later approved | No for strict run |
| CAMD-DPO pairs | teaches preference after clean rebuild | Yes, after rebuild |
| Adversarial prompts | eval/guard fixtures | No for strict run |
| Code/structured examples | eval/guard fixtures | No for strict run |
| Foreign-language examples | tests and optionally teaches period-register transfer | Low to medium |

## Hard Contamination Gates

Reject any `chosen`, `rejected`, or SFT target containing:

- act/scene headers,
- `Enter`, `Exit`, `Exeunt`,
- bracketed stage directions,
- all-caps speaker labels,
- Project Gutenberg front matter,
- Context Graph implementation notes,
- SITREP text,
- internal file paths unrelated to user task,
- prompt echo at the first sentence,
- exact raw prompt repeated in response.

Regex examples:

```text
\bACT\s+[IVXLC]+\b
\bSCENE\s+[IVXLC]+\b
\bEnter\s+[A-Z]
\bExit\b|\bExeunt\b
^\s*[A-Z][A-Z\s]{2,}\.
IMPL-PHASE-|SITREP|context-graph|/home/cabdru/contextgraph
```

These are hard fails. Do not "downweight" them.

## Anti-Memorization Gates

The target is style replication, not semantic copying.

Reject or mark as quotation-only if:

- longest common substring against the canon exceeds a threshold,
- 5-gram or 8-gram overlap is high,
- MinHash similarity against any passage is high,
- the response starts with a known Shakespeare line,
- the response contains a full sonnet stanza unless explicitly requested.

Suggested thresholds for non-quotation training:

- longest common substring under 120 characters,
- 8-gram overlap under 0.08,
- no complete canonical line longer than 10 words.

## SFT Dataset Design

Recommended SFT mix for `v5.0-tct`:

| Bucket | Count | Notes |
|---|---:|---|
| Modern-topic bridge | 4,000 | science, tech, mundane, social, advice, history, culture. |
| Code and structured | 800 | Python, Go, SQL, JSON, YAML, shell, regex. |
| Emotional and interpersonal | 800 | grief, love, shame, apology, conflict, encouragement. |
| Adversarial style attacks | 800 | style-breaking prompts answered in character. |
| Cross-lingual prompts | 500 | Spanish, French, German, Italian, Portuguese, Japanese, Chinese, Russian. |
| Raw-style anchors | 1,000 | cleaned short passages only, no headers, no long exact dumps. |
| Register targeted | 1,000 | sonnet, soliloquy, comic prose, tragic command, plain explanation. |
| Gap-hunter records | 1,000 | only after guard-scored and anti-memorization-filtered. |

Total: about 9,900 records. More records are not better unless they teach a distinct behavior.

## Bridge Example Generation Policy

Bridge examples may be teacher-generated only under a strict verification regime,
but they are not the default path for `v5.0-tct`. The safer default is to use
the 249k+ real Context Graph-derived Shakespeare signals for selection,
weighting, contrastive mining, constellation calibration, and runtime guards.

If generated bridge examples are used at all:

1. The prompt is human-authored or generated from a controlled prompt bank.
2. A modern factual answer is generated or supplied.
3. A Shakespeare-style answer is generated by v2.1 or a stronger teacher.
4. The answer is checked for:
   - style reward,
   - content equivalence to the modern answer,
   - no memorized Shakespeare overlap,
   - no scene/stage contamination,
   - no loops,
   - parser/compiler pass where applicable.
5. The record is labeled with external provenance and synthetic status.

Keep bridge data as externally verified supervision, not recursively generated
self-training. Do not use outputs from the candidate v5 model to train v5.

## Derived-Signal Use

The large signal catalog is not automatically a clean SFT target. Use it for:

- style profile vectors,
- semantic topics,
- register and meter tags,
- work/genre labels,
- cross-embedder correlations,
- constellation membership,
- sample weights,
- guard threshold calibration,
- hard-negative mining.

Only copy a record into SFT/DPO if its target text passes the same physical
contamination, length, memorization, and schema gates as any other training row.

For the strict "train only on Shakespeare's writing" run, assistant targets must
be real Shakespeare text only. Generated bridge answers, adversarial answers,
modern-topic compositions, and test fixtures may be used for evaluation and guard
calibration, but not as SFT target text.

Training candidate policy:

```text
assistant target = Shakespeare writing only
scene titles = reject
act headers = reject
stage directions = reject
speaker labels = reject
Project Gutenberg boilerplate = reject
internal Context Graph notes = reject
duplicate passage through multiple derived labels = deduplicate or downweight
```

The derived labels still matter. They should condition selection, weighting, and
coverage, but they must not multiply one passage into many high-weight target
rows without an explicit balancing rule.

## DPO Pair Design

Every DPO pair must satisfy:

```text
same or compatible content
large style quality gap
clean chosen
clean rejected
no scene headers
no internal notes
no exact Shakespeare copying unless quotation-labeled
```

Current DPO exports are not trusted for v5 training. The preflight FSV found
missing score traces in `shakespeare_dpo_clean.jsonl` and scene/stage/internal
test contamination in CAMD exports. Rebuild DPO from clean derived signals before
running preference training.

Recommended pair types:

| Pair type | Chosen | Rejected |
|---|---|---|
| Style transfer | Shakespeare-style answer | modern answer with same content |
| Pastiche correction | grammatically valid Shakespeare-style answer | broken archaic pastiche |
| Injection resistance | in-character refusal or answer | compliant modern style-drop |
| Code style | valid code plus Shakespeare comments/explanation | invalid code or style-dropped code |
| Loop avoidance | coherent Shakespeare answer | archaic-token loop |
| Structured output | valid schema answer | invalid decorated schema |
| Cross-lingual | period-register target | modern language style-drop |

## CAMD Pair-Mining Rules

Use content gates and style gates separately:

### Content Equivalence Gate

Use:

- E1,
- E10,
- E14,
- E11 entity overlap,
- task-specific parser checks.

`chosen` and `rejected` should be semantically close when the pair is teaching style. They may be semantically different only for explicit adversarial or refusal categories.

### Style Gap Gate

Use:

- E12,
- E13,
- E7,
- E9,
- E10,
- optional extended style views only after calibration.

Require a minimum style reward gap. For auto-mined data, start strict:

```text
chosen_style >= calibrated p50 Shakespeare held-out
rejected_style <= calibrated p25 modern controls
gap >= 0.15
```

Do not use fixed 0.45/0.30 thresholds until recalibrated after E14 and extended views.

## Dataset FSV Before Training

Before any training run:

1. `wc -l` all files.
2. sample 200 records manually or via report.
3. run contamination regex over every field.
4. run anti-memorization overlap over every target.
5. compute per-bucket counts.
6. verify no eval prompt appears in train.
7. verify all DPO pairs have score traces.
8. write `dataset_fsv_report.md`.
9. run `python3 scripts/shakespeare_v5_tct_preflight_fsv.py` and inspect the
   SQLite source-of-truth database plus copied smoke JSONL files.

Training must not start until dataset FSV is green.
