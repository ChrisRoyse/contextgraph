# [Feature/System Name] Specification

## Intent
What this system/feature should accomplish from the user's perspective.
Why it needs to exist.

## Constraints
- Non-negotiable requirements (security, performance, compliance)
- Boundaries of the system
- What this spec explicitly does NOT cover

## Behavior
Detailed description of expected behavior in various scenarios.
Written from the user's/caller's external perspective.
Include edge cases, error conditions, and degradation modes.

## Interfaces
- APIs (inputs, outputs, error responses)
- Data models
- Integration points with other systems

## Dependencies
- External services and their expected behaviors
- Internal modules this depends on
- Assumed infrastructure

## Acceptance Criteria
What "done" looks like — described behaviorally, not structurally.
These map directly to scenario definitions.

## Anti-Patterns
What the implementation should explicitly NOT do.
Common pitfalls to avoid.
